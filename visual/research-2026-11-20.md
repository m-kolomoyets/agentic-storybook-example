# Visual-regression options for `storybook-mcp` (SB 11 beta + Vite 8 + React 19 + Vitest 5 browser)

Researched 2026-11-20. Versions from the npm registry (`npm view`) on that date. Stack baseline (from `storybook-mcp/package.json`): `storybook@11.0.0-beta.3`, `@storybook/addon-vitest@11.0.0-beta.3`, `vitest@5.1.1`, `@vitest/browser-playwright@5.1.1`, `playwright@1.65.1`, Node >=24, pnpm 11. **Already installed:** `chromatic@18.15.1` and `@chromatic-com/storybook@5.6.0` (addon registered in `.storybook/main.ts`). "unverified" = not confirmed in a primary source.

## 2. Pros / cons

### A) Chromatic

**Pros**

- Already installed (`chromatic`, `@chromatic-com/storybook`); addon peer covers SB 11.
- Cross-browser (Chrome/Firefox/Safari/Edge) on paid plans; consistent cloud rendering, no Docker.
- TurboSnap cuts cost/time; SB11 `preview-stats.json` now has full graph (better tracing).
- Mature review: UI Review, flake filter, quarantine, a11y regression baselines, in-Storybook Visual Tests panel.
- Hosts Storybook + Storybook MCP server per build. **Cons**
- Most expensive paid tiers; Free = Chrome only.
- Renders outside your Vitest run (separate `storybook build`); differences between local Vitest and cloud are possible.
- Proprietary, no self-host; baselines live only in Chromatic.
- `@chromatic-com/vitest` path pins an internal `storybook@10.2.13` — avoid alongside SB 11.
- Docs still list Node 18/20/21 as guaranteed (project is Node 24 — works in practice? unverified).
- Tailwind v4 scanned/`@plugin` files must go in `--externals` for TurboSnap correctness.

### B) Argos

**Pros**

- Plugs directly into the existing `storybookTest()` Vitest project; screenshots exactly what tests rendered.
- Cheaper ($100/mo Pro; Storybook overage $0.0015); explicit SB 11 prerelease + Vitest ≥4 support.
- Open-source diff engine + platform (MIT), deterministic, explainable; layout-shift detection.
- Git merge-base baselines, stacked PRs, flaky detection w/ fingerprints, PR comment + statuses.
- GHA OIDC/tokenless auth (no secret); `argos deploy` gives hosted SB previews.
- Low lock-in: reads Chromatic modes; CLI exports baselines. **Cons**
- Free Hobby is single-person only — team review needs Pro.
- You own render stability (fonts, Chromium flags, pinned browser); no cross-browser cloud.
- No dependency-graph skipping like TurboSnap (only subset builds) — unverified.
- No local diff view (local runs only write PNGs).
- Self-host unsupported in practice; data in US/EU w/o residency choice; no per-build delete.

### C) DIY `toMatchScreenshot`

**Pros**

- Zero cost, zero vendor, data never leaves repo/CI.
- Native to Vitest 5 browser mode; same run as play + axe tests.
- Fully deterministic if run in pinned `mcr.microsoft.com/playwright:v1.65.1-noble`.
- Simple mental model: PNG in git, PR diff shows binary changes. **Cons**
- No review/approval UI; must build HTML report + CI artifact/Pages.
- Baselines in git (repo bloat → maybe Git LFS); stale files not pruned; platform-suffixed names force Docker for every update (mac devs).
- A mismatch fails the test → blocks CI rather than "review & approve".
- No flake history, no TurboSnap-like reuse, no branch-aware baselines (merge conflicts on PNGs).
- Community helpers (`storybook-addon-vrt` 0.4.2, `storybook-addon-vis` 4.8.0, `vitest-plugin-vis` 5.7.0) peer `vitest ^4` / `storybook ^10` → not Vitest 5/SB 11-ready; write own setup file.
- Docker image Node version may not satisfy `engines.node >=24` (unverified; Docker not checked).

## 3. Integration recipes (this stack, pnpm)

### A) Chromatic (Storybook path — recommended over `@chromatic-com/vitest`)

```bash
# already present: chromatic@18.15.1, @chromatic-com/storybook@5.6.0
pnpm exec chromatic --project-token=$CHROMATIC_PROJECT_TOKEN --build-script-name=build-storybook --only-changed --exit-zero-on-changes
```

`chromatic.config.json` (committed; `projectId` required by the Visual Tests addon):

```json
{
    "projectId": "Project:<id>",
    "buildScriptName": "build-storybook",
    "onlyChanged": true,
    "externals": ["src/styles/**", "public/**"],
    "autoAcceptChanges": "main",
    "exitZeroOnChanges": true
}
```

Modes (`.storybook/modes.ts` + story/preview `parameters.chromatic.modes`); threshold `parameters.chromatic.diffThreshold`. SB11: set default viewport via `initialGlobals.viewport`, not removed `parameters.viewport.defaultViewport`.

GitHub Actions:

```yaml
- uses: actions/checkout@v6
  with: { fetch-depth: 0 } # git history needed for baselines/TurboSnap
- uses: pnpm/action-setup@v4
- uses: actions/setup-node@v6
  with: { node-version: 24, cache: pnpm }
- run: pnpm install --frozen-lockfile
- uses: chromaui/action@latest
  with:
      projectToken: ${{ secrets.CHROMATIC_PROJECT_TOKEN }}
      buildScriptName: build-storybook
      onlyChanged: true
      exitZeroOnChanges: true
```

Env: `CHROMATIC_PROJECT_TOKEN`. Gitignore: `build-storybook.log chromatic.log chromatic-build-*.xml chromatic-diagnostics.json`.

(Alternative, not advised here: `pnpm add -D @chromatic-com/vitest@1.0.4`, `chromaticPlugin({ turboSnap: true })` in vitest config, then `chromatic --vitest --only-changed`; archives DOM during Vitest run, re-renders in Chromium cloud; pulls `storybook@10.2.13`.)

### B) Argos

```bash
pnpm add -D @argos-ci/storybook@6.5.0 @argos-ci/cli@6.14.0
```

`vitest.config.ts` — add to existing `storybook` project:

```ts
import { argosVitestPlugin } from '@argos-ci/storybook/vitest-plugin';
// ...
plugins: [
  storybookTest({ configDir, storybookScript: 'pnpm storybook' }),
  argosVitestPlugin({ uploadToArgos: !!process.env.CI }),
],
test: {
  name: 'storybook',
  browser: {
    enabled: true,
    headless: true,
    provider: playwright({ launchOptions: { args: ['--disable-lcd-text', '--font-render-hinting=none'] } }),
    instances: [{ browser: 'chromium' }],
  },
  // SB 11: no .storybook/vitest.setup.ts with setProjectAnnotations (throws SB_ADDON_VITEST_0002)
},
```

Extra shot in play: `import { argosScreenshot } from '@argos-ci/storybook/vitest'; await argosScreenshot(ctx, 'opened');`. Modes: `parameters.argos.modes`. Full-page: `parameters.argos.fitToContent = false`. Gitignore `./screenshots`.

GitHub Actions:

```yaml
permissions: { contents: read, id-token: write }   # enables OIDC instead of ARGOS_TOKEN (must enable in project)
steps:
  - uses: actions/checkout@v6
  - uses: pnpm/action-setup@v4
  - uses: actions/setup-node@v6
    with: { node-version: 24, cache: pnpm }
  - run: pnpm install --frozen-lockfile
  - run: pnpm exec playwright install --with-deps chromium
  - run: pnpm test:storybook            # vitest run --project=storybook
    env: { ARGOS_TOKEN: ${{ secrets.ARGOS_TOKEN }} }
  - run: pnpm build-storybook            # optional: hosted preview
  - run: pnpm exec argos deploy ./storybook-static
    env: { ARGOS_TOKEN: ${{ secrets.ARGOS_TOKEN }} }
```

Run on `push: main` too (establishes auto-approved baseline). Env: `ARGOS_TOKEN` (Settings → Authentication), optional `ARGOS_REFERENCE_BRANCH`, `ARGOS_BUILD_NAME`-style options via plugin `buildName`. Mark `argos` status required in branch protection.

### C) DIY

No new deps. `vitest.config.ts` (storybook project):

```ts
test: {
  name: 'storybook',
  setupFiles: ['./.storybook/vrt.setup.ts'],
  browser: {
    enabled: true, headless: true,
    provider: playwright({ launchOptions: { args: ['--disable-lcd-text', '--font-render-hinting=none'] } }),
    instances: [{ browser: 'chromium', viewport: { width: 1280, height: 800 } }],
    expect: {
      toMatchScreenshot: {
        comparatorName: 'pixelmatch',
        comparatorOptions: { threshold: 0.2, allowedMismatchedPixelRatio: 0.001 },
        // optional: drop platform suffix since baselines are only ever made in Docker/linux
        resolveScreenshotPath: ({ root, testFileDirectory, screenshotDirectory, testFileName, arg, browserName, ext }) =>
          `${root}/${testFileDirectory}/${screenshotDirectory}/${testFileName}/${arg}-${browserName}${ext}`,
      },
    },
  },
},
```

`.storybook/vrt.setup.ts` (sketch — **unverified** that the story root locator and auto-naming behave inside `afterEach` under addon-vitest; check `storybook-addon-vrt` source for reference):

```ts
import { afterEach, expect } from 'vitest';
import { page } from 'vitest/browser';

afterEach(async ({ task }) => {
    if (task.result?.state === 'fail') return;
    if (process.env.VRT !== '1') return; // only in Docker job
    const root = document.body.firstElementChild as HTMLElement; // adjust to actual story root
    await document.fonts.ready;
    await expect.element(page.elementLocator(root)).toMatchScreenshot();
});
```

Opt out per story with a tag (e.g. `tags: ['!vrt']` + `storybookTest({ tags: { exclude: ['no-vrt'] } })`).

Commands (pinned container; same for local devs and CI):

```bash
docker run --rm -v "$PWD":/work -w /work -e CI=1 -e VRT=1 --ipc=host \
  mcr.microsoft.com/playwright:v1.65.1-noble \
  bash -lc "corepack enable && pnpm install --frozen-lockfile && pnpm vitest run --project=storybook"
# update baselines:
#   ... pnpm vitest run --project=storybook --update
```

CI: same container as `container: mcr.microsoft.com/playwright:v1.65.1-noble`; on failure upload `.vitest/attachments/**` and `src/**/__screenshots__/**` + generated `vrt-report/index.html` (small Node script: for each `*-actual.png`/diff in attachments, render reference | actual | diff side-by-side) as artifact or GitHub Pages. Manual `workflow_dispatch` "update-screenshots" job that runs `--update` and commits PNGs. Consider Git LFS for `**/__screenshots__/**/*.png`. Ensure image Node ≥24 or install it (unverified what Node the image ships).

## 4. Known incompatibilities / risks (SB 11 beta, Vitest 5)

- **SB 11 removes `@storybook/test-runner`** → Argos' `@argos-ci/storybook/test-runner` and Storycap-test-runner flows are dead; use Vitest plugin paths only.
- **SB 11 `setProjectAnnotations` in Vitest setup files throws** (`SB_ADDON_VITEST_0002`). Argos docs' commented `setupFiles: ['.storybook/vitest.setup.ts']` must stay off; DIY setup file must not call it.
- **SB 11 Vite `preview-stats.json` now full graph** → Chromatic TurboSnap needs `chromatic` ≥18.13.1 (have 18.15.1). Tailwind v4 scanned sources/`@plugin` files aren't traced → add `--externals`.
- **SB 11 removed `parameters.viewport.defaultViewport`** → modes/viewports must use globals (`initialGlobals.viewport`); affects all three.
- **SB 11 `storybook dev` CSP `frame-ancestors`** restricts embedding to localhost; impact on Chromatic Visual Tests addon / Storybook Connect embedding = unverified (built Storybooks unaffected).
- **SB 11 beta itself**: cloud `storybook build` (Chromatic) and plugin integrations may break on beta bumps; Argos/Chromatic declare `^11.0.0-0` peers but SB11-beta-specific testing is unverified.
- **`@chromatic-com/vitest` depends on `storybook@10.2.13`** → second Storybook copy next to 11 beta; Chromatic docs warn about Storybook `overrides` causing `ERR_INVALID_ARG_TYPE`. Avoid; use Storybook CLI path.
- **Chromatic Vitest path requires Chromium** instances; other providers unsupported.
- **Community DIY helpers peer `vitest ^4`** (`storybook-addon-vrt`, `storybook-addon-vis`, `vitest-plugin-vis`) → peer conflicts with Vitest 5.
- **Vitest 5** requires Node ≥22.12 and Vite ≥6.4 (fine). No documented `toMatchScreenshot` breaking change found (unverified).
- **`storybook/test` expect ≠ Vitest expect** in SB 11 (bundled `@vitest/expect` 5): `toMatchScreenshot` must come from `vitest` (`expect.element`), not `storybook/test`.
- **Platform-suffixed baselines** (`-darwin` vs `-linux`) in DIY; Argos avoids by uploading CI-only; Chromatic avoids via cloud.
- **Chromatic Node support statement** (18/20/21) lags project's Node 24 (unverified issue).
